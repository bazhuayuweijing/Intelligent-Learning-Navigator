# A3智学领航 - 开发说明书

## 项目概述

本项目为第十五届中国大学生计算机设计大赛软件应用与开发赛道A3赛题：基于大模型的个性化资源生成与学习多智能体系统。

**核心目标**：构建一个面向高等教育的多智能体个性化学习系统，通过AI技术实现学生学习画像的自动构建、个性化学习资源的智能生成、学习效果的精准评估、教师端班级管理与记忆巩固提醒。

## 技术栈

| 层级 | 技术 | 版本 | 用途 |
|------|------|------|------|
| **后端框架** | Flask | 3.0.0 | Web框架，Python生态，Hackathon友好 |
| **数据库** | SQLite（Flask-SQLAlchemy） | 3.1.1 | 轻量级零运维关系型数据库 |
| **大语言模型** | 讯飞星火Spark（lite） | 官方API | 生成、评估、辅导核心推理 |
| **AI视频生成** | 火山引擎豆包（doubao-seedance） | 官方API | 教学视频自动生成 |
| **知识检索** | TF-IDF | - | 轻量级知识增强（无需向量库） |
| **语音识别** | 讯飞WebSocket API | - | 语音转文字多模态输入 |
| **前端** | Bootstrap 5 + Jinja2模板 | 5.3.3 | 后端渲染，无需前后端分离 |
| **图表** | Mermaid.js | CDN | 思维导图渲染（树状布局） |
| **PDF导出** | fpdf2 | 2.7.9 | 评估报告PDF导出（支持中文） |
| **部署** | Docker + gunicorn | 最新 | 标准容器化部署 |

**技术选型理由**（评分表要求"技术选型给出对比差异"）：

- **Flask vs Django/FastAPI**：团队对Flask最熟悉，A3赛题强调"智能体逻辑实现"权重高于高并发能力。Flask + Blueprints的模块化结构清晰对应多个智能体的组织。如果追求API性能会选FastAPI，如果需要开箱管理后台就选Django——但我们的场景核心是智能体逻辑，Flask够用且开发效率最高。
- **SQLite vs MySQL/PostgreSQL**：系统面向个人学习场景，无需高并发。SQLite零配置、零运维、数据即文件，演示时直接拷贝即可迁移。实际部署如需多用户并发可无缝切换到PostgreSQL（Flask SQLAlchemy已抽象）。赛题未要求分布式，不引入数据库服务端代价。
- **讯飞星火 vs GPT-4/BERT**：国产化要求优先，讯飞星火在教育场景的中文理解能力经过验证。对比GPT-4：成本可控（按量计费无额度限制）、符合国产化方向、支持流式输出。对比本地部署的BERT：推理质量不在同一级别，教育场景需要的是生成能力而非简单的分类。
- **火山引擎豆包 vs 即梦/可灵**：教学视频生成需要稳定的API服务与可控成本。火山方舟（Ark）提供标准OpenAI兼容接口，支持任务提交/查询的异步模式，配合LLM生成的视频脚本（分镜/配音稿/字幕）形成完整教学视频生成链路。对比即梦、可灵等：火山引擎文档完善、限流宽松、模型（doubao-seedance）视频质量高。
- **TF-IDF vs 向量检索**：知识库规模在10篇以内，TF-IDF的Bag-of-Words模型足以实现文档检索，无需引入向量数据库。如需扩展到百篇以上，可升级到FAISS/Chroma（代码中retriever模块已预留接口）。
- **后端渲染 vs 前后端分离**：核心Agent逻辑在后端，前端仅为展示层。后端渲染保持技术栈一致，减少跨团队沟通成本。
- **fpdf2 vs reportlab**：评估报告PDF导出需要中文字体支持，fpdf2轻量且自动查找系统中文字体（`_find_chinese_font_path`），集成成本低。

## Flask应用初始化流程

```
load_config → init_db → register_blueprints → register_jinja_filters → run_app

1. config.py: 加载LEVELS/DIMENSIONS/SUBJECTS等配置常量 + 各API密钥（环境变量）
2. models.py: 15张表（User/Assessment/ResourceHistory/LearningPath/TutorSession/Evaluation/
              LearningBehavior/EvaluationReport/LearningPlan/ContentSafetyLog/AsyncTask/
              ProfileConversation/GeneratedResource/WrongQuestion/KnowledgePoint）
3. Blueprints: 4个蓝图注册（evaluate_bp/tutor_bp/admin_bp/teacher_bp）
4. Jinja2 filters: 注册模板自定义过滤器（fromjson等）
5. 启动Flask开发服务器(DEMO_MODE→所有API降级，无外部依赖)
```

## 多智能体调度架构

```
GeneratorCoordinator
    ├── context 注入 (unified context with student_profile)
    ├── agent 分派 (8个生成Agent: document/mindmap/quiz/case/video/book_paper/multimedia/trap_exam)
    ├── 画像感知调整 (weak_points → content_style mapping)
    └── 异常托管 (try/catch → fallback template)

每个Agent:
    generate(context) → dict
        1. 从context中提取subject/topic/level/student_profile
        2. 构建LLM prompt（包含画像信息）
        3. call_llm(sys_prompt, user_prompt)
        4. LLM成功 → 解析/写入DB
        5. LLM失败 → fallback模板内容
        6. SafetyFilter校验 → 通过/拒绝
```

## 生成Agent清单

| Agent | 类型标识 | 职责 |
|-------|---------|------|

## 核心外部服务

### 讯飞星火（LLM）
- API: https://spark-api-open.xf-yun.com/v1/chat/completions
- 模型: lite（环境变量可覆盖）
- 封装: llm_client.py spark_chat()，带重试与降级

### 火山引擎（AI视频生成）
- API: https://ark.cn-beijing.volces.com/api/v3
- 模型: doubao-seedance-1-0-pro-250528（环境变量可覆盖）
- 流程: 提交任务(submit) → 轮询状态(query) → 视频生成
- 降级: API不可用时仍可生成视频脚本（LLM），不影响核心功能

### 代码批改
- evaluate_python_code(): 基于讯飞星火，对提交的Python代码评分+纠错

## 设计模式

- **Blueprint模块化**：每个路由模块独立，按功能组织
- **Template Method**：BaseGeneratorAgent定义generate骨架，子类实现具体逻辑
- **Pipeline架构**：评估引擎按评估→校验→存储→分析串联
- **多级降级**：LLM→规则→模板三级降级（STT五级降级，视频API不可用降级为脚本生成）
- **Repository模式**：通过SQLAlchemy统一数据访问
- **继承复用**：VideoAgent/BookPaperAgent继承ResourceRecommenderAgent复用资源库
